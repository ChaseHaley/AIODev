# AIODev startup instructions

Read and follow `AGENTS.md` in this directory before project work. It routes to the
Obsidian project home, organization rules, engineering standards, and work dashboard.

Always read the vault file
`C:\Users\chale\Obsidian Vaults\Main\Main\AIODev\System\Idea capture.md`.
When the owner says an improvement "would be nice" or mentions a future feature,
capture it durably in the appropriate individual work item during that conversation.
Search for existing related work, preserve the request and origin, add precise links,
and set work-item properties so native Bases views include the item automatically.
Use the intake queue if the area or delivery stage is uncertain.
Tell the owner where it was recorded. Capturing an idea does not approve implementation.

The Obsidian vault is authoritative; these startup files contain routing rules only.
The vault is a Git repository: when you finish changing notes, commit them there
(see AGENTS.md and the vault's Organization guide, Version control).
Use ID-only work/decision filenames and concise titles with a colon after the ID.
Do not use long-dash separators. Confirm links resolve to populated notes after
trimming whitespace from targets, and verify any linked section exists.
